# Risk-Ranked Classifier Design

## Goal

For verifier-confirmed, single-bread crops, automatically return the correct
Top-1 SKU for at least 95% of registered evaluation crops while keeping the
registered automatic error rate below 5%.  All remaining registered crops return `Unknown` with
three ranked candidates containing the truth at least 90% of the time.  Batch 1 is development-only;
Batch 2 remains untouched until the policy is frozen.

This goal applies to the classifier input contract only.  It does not claim
Detector, Verifier, or OOD performance.

## Current Limitation

The current policy combines RepViT and DINO scores with fixed rules.  An
exploratory local-recheck policy produced 460 correct automatic decisions out
of 509 Batch 1 crops (90.4%), but also 22 wrong automatic decisions.  A single
fused-confidence threshold that removes every observed automatic error reduces
correct coverage to 259/509 (50.9%).  Therefore a scalar threshold cannot meet
the target.

## Architecture

```text
Verified single-bread crop
  -> canonical 5% / 10% / 15% views
  -> RepViT-M1: 20-way probabilities, feature, crop disagreement,
                 prototype distance
  -> DINOv3: global 20-way similarities
  -> candidates = DINO Top-5 union RepViT Top-2 (at most seven)
  -> DINO local evidence against balanced per-SKU patch coreset
  -> FusionRanker: candidate reranking from all per-candidate evidence
  -> RiskCalibrator: accept the ranked SKU or return Unknown + Top-3
```

`FusionRanker` and `RiskCalibrator` have different responsibilities.  The
ranker improves SKU ordering; the calibrator only estimates the risk of the
ranked answer and cannot change its SKU.  The pair avoids using confidence as a
proxy for class discrimination.

## Evidence Contract

For each candidate SKU, the collector writes a versioned full-evidence row:

- RepViT probability, logit-margin, rank, crop disagreement, and nearest
  prototype distance.
- DINO global similarity, normalized probability, global margin, and rank.
- DINO local raw similarity, candidate-local margin, matched product-patch
  count, and product-patch ratio.
- Candidate provenance, model hashes, preprocessing hash, and local-bank hash.

The local bank remains an equal-cap, source-balanced, deterministic coreset.
The present eroded-box patch mask remains explicitly recorded as a fallback
until the Verifier provides a foreground mask.

## Training and Decision Rules

1. Split Batch 1 by capture group into out-of-fold folds.  Every prediction
   used to train or choose the risk policy must be generated by a ranker that
   did not train on that capture group.
2. Train a regularized candidate ranker on the full evidence rows.  The output
   is a candidate score, not an automatic decision.
3. Train a separate risk calibrator on out-of-fold Top-1 rows using ranker
   score/margin plus model disagreement and OOD evidence.  It yields an
   acceptance risk score.
4. Select the most conservative Batch 1 acceptance threshold with registered
   automatic error rate below 5% and at least 95% correct automatic coverage.
   If no such threshold exists, publish the measured maximum coverage and do
   not relax the error-safety condition.
5. Freeze model, ranker, calibrator, and threshold.  Run once on disjoint,
   locked Batch 2.  A failure on Batch 2 is a failed acceptance result, not a
   reason to tune the policy.

## Failure Behavior and Reporting

- Invalid/missing model or evidence artifact: fail closed as `Unknown`.
- Ranker/candidate contract failure: `Unknown` with the model-fusion Top-3 and
  a machine-readable reason.
- Automatic decision: SKU, ranker confidence/risk, original box, `fusion_ranked`
  path, and complete provenance.
- Unknown: exactly three unique SKUs, their rank scores, and reason.

The report must include automatic correct/error counts, correct-Top-1 coverage,
Unknown count/reasons, registered Unknown Top-3 recall (at least 90%), candidate
recall, and total/RepViT/DINO latency percentiles.  The target requires an
independent locked registered-product set; it is not an OOD claim.

## Verification

- Unit tests for full-evidence serialization, candidate feature extraction,
  capture-group split isolation, ranking, risk threshold selection, and
  `Unknown` fallbacks.
- Regression tests for the repeated hard pairs 20/19, 4/19, 4/8, and 9/14.
- Batch 1 development report used only for artifact selection.
- One fixed-artifact Batch 2 report with no threshold selection.

## Frozen Artifact and Result

The immutable `fusion_policy_v1.json` contains the final Batch-1 ranker,
risk-calibrator and one threshold (`0.9980055438811386`), together with all
model, preprocessing, support and local-bank hashes.  The configured runtime
loads it only when those hashes match.  A RepViT direct decision remains
available under its separate fail-closed gate; the configured v3 gate is
intentionally closed, so the current accepted path collects the full DINO
global/local evidence and emits either `fusion_ranked` or `Unknown`.

With the artifact fixed from Batch 1, the independent 522-crop Batch 2 report
has 510 correct automatic results (97.70% correct Top-1 coverage), 12 automatic
errors (2.30% automatic error rate), and no Unknown outputs.  Its conditional
Unknown Top-3 recall is therefore 1.0 (there were no Unknown cases).  This is a
classifier-crop result only; it is not a detector/verifier or OOD claim.
