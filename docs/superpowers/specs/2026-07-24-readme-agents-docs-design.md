# README 및 AGENTS 문서 설계

- 작성일: 2026-07-24
- 상태: 사용자 구성 승인 완료, 문서 구현 전 검토

## 1. 목적

이 설계는 `README.md`와 `AGENTS.md`가 Bakery Scanner의 최종 목표를
일관되게 설명하도록 문서의 역할과 내용을 정의한다. 현재 구현 진척이나
완료된 기능 목록은 다루지 않는다.

## 2. 공통 제품 목표

고정된 운영 환경에서 입력된 스캔 이미지로부터 빵의 품목, 수량, 위치를
추론한다. 파이프라인은 다음 순서를 따른다.

1. Detector(D-FINE/RTMDet)가 빵의 위치와 후보 박스를 검출한다.
2. Verifier가 후보를 검증하여 누락, 중복, 비대상 물체 오검출이 없는 최종
   대상 영역을 확정한다.
3. Classifier(MobileNetV4/RepViT)가 각 영역의 제품 종류와 분류 신뢰도를
   산출한다.
4. 신뢰도가 충분하고 혼동 가능성이 낮은 결과는 즉시 확정한다.
5. 저신뢰 또는 난분류 결과에만 DINOv3 재확인을 수행한다.
6. 재확인으로 등록 제품임이 입증되면 해당 품목으로 확정하고, 충분히
   확신할 수 없으면 `Unknown`으로 처리한다.
7. 최종 결과로 품목, 수량, 위치, 판정 신뢰도를 제공한다.

## 3. 품질 및 성능 기준

- 정확성의 출하 기준은 고정된 운영 조건과 사전에 잠근 승인 평가셋에서
  오분류, 누락, 중복, 비대상 검출이 각각 0건인 것이다.
- `오인율 0%`를 검증하지 않은 입력 분포까지 포함한 절대적 보장으로
  표현하지 않는다.
- 불확실한 등록 제품명을 억지로 반환하지 않고 `Unknown`으로 보수적으로
  처리한다.
- 전체 파이프라인의 성능 목표는 현재 기준 PC의 CPU 단일 이미지 추론
  0.5초 이하이다.
- 속도 최적화는 승인 평가 기준을 유지하는 범위에서만 허용한다.

## 5. AGENTS.md 구성

`AGENTS.md`는 이 저장소에서 작업하는 코딩 에이전트의 최상위 개발
규칙이다.

1. 프로젝트 미션과 우선순위
2. 파이프라인 단계 및 단계별 단일 책임
3. 단계 간 데이터 계약
4. 판정 정책
   - Classifier 고신뢰 결과의 직접 사용
   - 저신뢰 및 난분류 결과에 한정한 DINOv3 실행
   - 확신 부족 시 `Unknown`
5. 정확성 불변 조건
   - 누락, 중복, 비대상 검출 방지
   - 품목별 수량과 박스 수 일치
   - 좌표의 원본 이미지 기준 유지
6. 성능 불변 조건
   - CPU 전체 추론 0.5초 목표
   - 단계별 지연 시간 측정
   - 정확성을 훼손하는 최적화 금지
7. 변경 및 검증 규칙
   - 변경 범위를 한 단계에 국한
   - 결정적이고 재현 가능한 평가
   - 회귀 테스트와 벤치마크 결과 확인
   - 임계값과 모델 버전을 코드에 산재시키지 않고 설정으로 관리
8. 완료 조건

AGENTS 문서는 기술 스택이나 아직 확정되지 않은 디렉터리 구조를 과도하게
고정하지 않는다. 대신 구현 전반에서 지켜야 할 책임 경계와 검증 가능한
완료 기준을 규정한다.

## 6. 용어와 출력 계약

- `Detector candidate`: Detector가 생성한 검증 전 후보 박스
- `verified region`: Verifier를 통과해 하나의 대상 빵에 대응하는 영역
- `classification confidence`: Classifier가 산출한 제품 분류 신뢰도
- `Unknown`: 등록 제품으로 확정할 근거가 부족한 품목
- `bbox`: 원본 이미지 좌표계의 `[x_min, y_min, x_max, y_max]`

개별 결과에는 최소한 품목 식별자, 위치, 신뢰도, 판정 경로를 포함한다.
집계 결과에는 품목별 수량을 포함한다. 판정 경로는 Classifier 직접 확정,
DINOv3 재확인, `Unknown` 중 하나를 구분할 수 있어야 한다.

## 7. 범위 제외

- 현재 구현 진척 보고
- 학습 데이터의 구체적인 수량과 경로
- 확정되지 않은 신뢰도 임계값
- 특정 하드웨어에 종속된 최적화 방법
- 설치 및 실행 명령어
- 모든 미지 입력에 대한 절대 무오류 보장

- 자리표시자나 미결정 항목을 포함하지 않는다.
- README의 제품 설명과 AGENTS의 개발 규칙은 동일한 파이프라인 순서를

- 정확성 목표는 승인 평가셋 기준으로 정의하며 `Unknown` 정책과
